# 버그 수정 워크플로우

GitHub 이슈 번호: $ARGUMENTS

## 실행 순서

1. **이슈 분석**: `gh issue view $ARGUMENTS`로 이슈 내용 확인. 관련 코드를 읽고 `git log`, `git blame`으로 변경 이력 파악
2. **TDD Red**: 버그를 재현하는 실패 테스트 작성. 테스트가 실패하는 것을 확인
3. **TDD Green**: 테스트를 통과시키는 최소한의 수정만 적용
4. **TDD Refactor**: 기존 테스트 전체 통과 확인 후 필요시 정리
5. **검증**: 실제 동작 확인 (빌드, 실행 등)
6. **커밋**: 커밋 메시지에 반드시 `#이슈번호` 포함

## 규칙

- 이슈가 없으면 작업하지 말 것. 먼저 이슈를 생성할 것
- 테스트 인프라가 없는 경우 수동 검증으로 대체하되 명시할 것
- 수정 범위를 최소화할 것. 관련 없는 코드 변경 금지
- 도메인에 따라 crawler-expert 또는 flutter-expert agent 활용
