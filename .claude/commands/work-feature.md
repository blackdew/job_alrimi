# 기능 구현 워크플로우

GitHub 이슈 번호: $ARGUMENTS

## 실행 순서

1. **이슈 분석**: `gh issue view $ARGUMENTS`로 요구사항 확인. 관련 코드의 기존 패턴과 컨벤션 파악
2. **영향 분석**: 변경이 다른 코드에 미치는 영향 분석. 의존성 확인
3. **구현**: 기존 패턴을 따라 최소한의 변경으로 구현
4. **검증**: 빌드 성공, 기존 기능 미훼손 확인
5. **커밋**: 커밋 메시지에 반드시 `#이슈번호` 포함

## 규칙

- 이슈가 없으면 작업하지 말 것. 먼저 이슈를 생성할 것
- 구현 전 사용자에게 방향을 확인받을 것
- 도메인에 따라 crawler-expert 또는 flutter-expert agent 활용
